nspawn 1.3.0 gives machines what `docker run` gives containers: several
networks with names on each, healthchecks, secrets, and the rest of the flags
(hostname, user, capabilities, tmpfs, devices, DNS, ulimits, signals). It is
the ground `nspawn compose` is built on in 2.0.0.

## Breaking changes

- **`ListNetwork()` is gone from the bus.** Deprecated in 1.2.0;
  `GetNetwork("bridge")` has the same machines.
- **`ps` shows the network by name.** The NETWORK column names a user-defined
  network with the machine's address on it (`front:10.99.1.2`) where it showed
  `veth`; the default network still shows the address alone.
- **`stop` takes several names**, like `kill`; scripts that passed one name
  see no difference.
- **Records of 1.3.0 on a 1.2 binary.** A 1.2 binary reads them, but starts a
  machine on its primary network alone, without its healthcheck, secrets and
  the new flags.

## New

- **Several networks per machine.** `--network` repeated joins several bridge
  networks, the first one primary; the default route goes through the first
  that is not internal. `--network-alias NAME` (or `NETWORK=NAME`) gives a
  machine more names on a network, `--network none` no interface but `lo`,
  and `network create --label` tags a network. Booted machines get one veth per
  network (`VirtualEthernetExtra=`), apps one per network in their namespace;
  every `/etc/hosts` lists the members of each network the machine is on with
  their names and aliases there.
- **Ports on one host address.** `-p 127.0.0.1:8080:80` publishes on one
  address of the host, as docker does; `-p 8000-8010:8000-8010` publishes a
  range, one mapping per port.
- **Healthchecks.** The image's `HEALTHCHECK`, or `--health-cmd` with
  `--health-interval`, `--health-timeout`, `--health-retries`,
  `--health-start-period` and `--health-start-interval` (`--no-healthcheck`
  turns it off), run a probe inside the machine from a unit bound to the
  machine's. `ps` shows `(healthy)`, `(unhealthy)` or `(health: starting)`,
  `inspect` the last probes, `events` a `health_status` on every change;
  `update` changes the healthcheck of a running machine.
- **The other run flags.** `--hostname`, `-u/--user`, `-w/--workdir`,
  `--cap-add`, `--cap-drop`, `--privileged`, `--read-only`, `--tmpfs`,
  `--shm-size`, `--device`, `--dns`, `--dns-search`, `--add-host`,
  `--ulimit`, `--oom-score-adj`, `--stop-signal`, `--stop-timeout`, `--init`
  and `--sysctl` (`net.*` in an app machine's namespace), remembered like the
  rest and shown by `inspect`. The user is resolved as docker resolves it,
  from the image's passwd and group files, by a stand-in for getent that
  nspawn binds: busybox has no getent, musl's (alpine) answers no
  initgroups, and a uid the passwd does not list runs all the same. A path
  the image declares as a volume with nothing mounted over it gets a note at
  start. `--hostname` reaches a booted machine as its `/etc/hostname`, over
  the image's.
- **Secrets.** `nspawn secret create NAME` keeps a secret encrypted with
  systemd-creds (the host's TPM2 where there is one, its credential key
  otherwise); `--secret NAME[:TARGET[:MODE[:UID:GID]]]` gives a machine the
  plaintext as a read-only file, `/run/secrets/NAME` by default, decrypted
  into a tmpfs of root's alone while it runs. `secret ls`, `secret inspect`
  and `secret rm` complete it; a secret a machine takes cannot be removed.
- **restart, pause, unpause, top.** `restart` is a stop and a start with the
  remembered options; `pause` and `unpause` freeze and thaw a machine's
  cgroup, `ps` showing it paused; `top` lists a machine's processes. `inspect`
  of a stopped machine shows the exit code of its last run.
- **exec** takes `-e`, `-w`, `-T`, `-i`, `-t` and `-d`, as docker exec does.
- **logs** takes `--until`, and several machines at once, every line behind
  its machine's name.
- **create** takes a reference that is not local and pulls it first, under
  its own name, as `run` does.
- **A named volume made on first use is seeded from the image**: what the
  image has at the mount point, owner and mode included, as docker does. A
  program that runs as a user (prometheus, grafana) finds its data directory
  its own.

On the bus: `PauseMachine`, `UnpauseMachine`, `MachineProcesses`,
`ListSecrets`, `GetSecret`, `CreateSecret`, `RemoveSecrets`; the options
`networks`, `aliases`, the `health_*` ones and docker's other flags on
`StartMachine`, `RunMachine` and `CreateMachine`; `labels` on
`CreateNetwork`; `until` on `Logs`; `workdir` and `detach` on `Exec`;
`exit_code`, `health` and the new record keys on `GetMachine`; see
`docs/DBUS.md`.

## Fixed

- **An app restarted was unreachable from the host for some seconds**: its
  new interface had a new MAC and the host's neighbour cache kept the old
  one until it was probed. An app's interfaces now take their MAC from their
  address, as docker's do, so a restart keeps it.

- **`--tmpfs /var/run` broke a machine**: it lands on `/run`, which is a
  tmpfs of every machine already and holds what systemd-nspawn keeps there.
  Such a tmpfs is left out, with a note.

- **Images with more than two layers did not mount on hosts with util-linux
  2.41** (Fedora 44, Arch): its fd-based mount rejects overlayfs's
  colon-separated `lowerdir=`. The layers are now mounted with one
  `lowerdir+=` each, which Linux 6.5 and newer take.

## Requirements

As for 1.2.0: systemd 255 or newer with systemd-nspawn and machined, Linux
6.5 or newer with overlayfs, `ip` and `nft`; secrets need `systemd-creds`
(part of systemd). nspawn-selinux gains rules for the files under
`/run/nspawn` (health verdicts, decrypted secrets).

## Known gaps

Secrets are not attached to mstack machines yet. `--sysctl` takes `net.*`
keys for app machines only. `--user` takes a name or a uid, not `uid:gid`.
`--init` is accepted and does nothing, since the stub init reaps anyway.
Healthchecks and the new flags apply at the next start of a machine, but
the healthcheck, which `update` applies at once.
