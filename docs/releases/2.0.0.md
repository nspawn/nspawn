nspawn 2.0.0 runs docker compose files, builds Dockerfiles with a builder of its
own, serves a read-only Docker API to the machines that mount docker's socket, runs
s6-overlay images as PID 1, hands machines GPUs through CDI, and takes the scripting
flags of docker's command line.

## Added

- **`nspawn compose`**, the files and commands of docker compose 5.6.0 on nspawn's
  machines: `config`, `up`, `down`, `create`, `start`, `stop`, `restart`, `kill`,
  `pause`, `unpause`, `rm`, `run`, `exec`, `ps`, `ls`, `logs`, `top`, `port`, `images`,
  `pull`, `build`, `scale`, `wait`, `cp`, `stats`, `events`, `volumes` and `version`,
  with docker compose's flags, output and errors. `alpha`, `attach`, `bridge`,
  `commit`, `export`, `publish`, `push` and `watch` are refused with a reason.
  - The files load as docker compose loads them: interpolation, `.env`, profiles,
    `include`, `extends`, overrides, `!reset` and `!override`, the schema's checks
    with the same messages. `config` prints what docker compose prints.
  - A service becomes a machine per replica, `PROJECT-SERVICE-N`, with docker
    compose's labels; its networks, volumes, secrets and configs are nspawn's, and a
    machine is made anew when its config hash or its image changes. `depends_on`
    orders compose's own starts and waits for its conditions.
  - [docs/COMPOSE.md](https://github.com/nspawn/nspawn/blob/2.0.0/docs/COMPOSE.md)
    lists every attribute and option with what nspawn compose does with it: supported,
    partly, ignored with a warning, or refused with a reason.
- **Dockerfile builds**: `nspawn build` runs a Dockerfile with a builder of nspawn's
  own, as `docker build` does.
  - The Dockerfile is read as BuildKit v0.33.1's frontend reads it; multi-stage builds,
    `ARG` and `--build-arg`, `--target`, `ONBUILD`, heredocs, `COPY --from --chown
    --chmod --parents --exclude --link`, `ADD` of archives and of URLs with
    `--checksum`, `RUN --mount` of the cache, bind, tmpfs and secret kinds, `--secret`,
    `--network`, `--add-host`, `--label`, `--pull`, `--no-cache`, `--no-cache-filter`,
    `-q`, `--iidfile` and `--push`. `.dockerignore` and `Dockerfile.dockerignore` are
    honored.
  - Every `RUN` runs under systemd-nspawn with the confinement of an app machine; a
    layer is the tar BuildKit writes of the same tree. A build taken whole from the
    cache gives the same image ID.
  - The build cache is listed by `builder du` and pruned by `builder prune` (`-a`,
    `--filter until=`, `--keep-storage`). Compose's `build:` sections, `compose build`
    and `up --build` use the builder.
  - On the bus: `BuildDockerfile`, `PruneBuildCache` and `BuildCacheUsage`.
- **A Docker API for proxies and dashboards.** A machine that mounts
  `/var/run/docker.sock` or `/run/docker.sock` from the host (or compose's
  `use_api_socket`) gets nspawn's Docker API there, API 1.51 down to 1.24: the
  machines as containers with their labels, networks and addresses, inspect, events,
  logs, stats, top and the networks. It changes nothing, except `POST
  /containers/ID/kill`. caddy-docker-proxy, Traefik, nginx-proxy with docker-gen and
  acme-companion, homepage and Dozzle find the machines with it. Each machine has its
  own socket, `nspawn-api@NAME.socket`, opened before it starts.
- **`nspawn auto-update`** gives the machines labelled `org.nspawn.auto-update=registry`
  (or podman's `io.containers.autoupdate=registry`) the image their tag names now: the
  machine is made anew from it with every option it had, and put back on the old image
  when the new one does not come up. `--dry-run` says which ones have an update
  waiting. The packages ship `nspawn-auto-update.timer`, daily and disabled. On the
  bus: `AutoUpdate` and `ImageDigest`.
- **s6-overlay images run as PID 1.** An image whose `/init` supervises it
  (linuxserver.io's, Home Assistant's) runs as an app with that program as PID 1 of the
  machine. `--init=false` asks the same of any app, and `--init` puts the program under
  the stub init; compose's `init:` follows.
- **GPUs and CDI devices.** `--device VENDOR/CLASS=NAME` takes the devices of the CDI
  specs under `/etc/cdi` and `/var/run/cdi`, their nodes, libraries, variables and
  hooks included, and `--gpus all|N|device=...` the NVIDIA (or AMD) ones; compose's
  `gpus:`, device reservations and CDI names in `devices:` too. The specs are read at
  every start.
- **docker's scripting flags.**
  - `--env-file` and `--label-file`, read as docker reads them, and `--mount
    type=bind|volume|tmpfs`, on `run`, `create` and `start`.
  - `--ip ADDRESS` (or `NETWORK=ADDRESS`) fixes an address on a network made with
    `network create`; compose's `ipv4_address` too.
  - `ps -q`, `ps --filter KEY=VALUE` (`name`, `label`, `status`, `network`,
    `ancestor`, `health`, `exited`, `volume`, `publish`, `expose`, `id`, `before`,
    `since`), `ps --format` with Go templates over docker's fields, `table` and
    `json`, and `ps --no-trunc`; `inspect -f TEMPLATE`.
  - `images prune [-a]`, `system df [-v]`, `system prune [-a] [--volumes]` and
    `network prune --filter`; on the bus `PruneImages` and `DiskUsage`.
  - `network connect [--alias] [--ip] NETWORK MACHINE` and `network disconnect`, at
    once on a running app or booted machine; on the bus `ConnectNetwork` and
    `DisconnectNetwork`.
  - `wait NAME...` prints the exit codes of machines once they stop, and `port NAME
    [PORT[/PROTO]]` the ports a machine publishes.
- An app's own network namespace gets `net.ipv4.ping_group_range=0 2147483647` and
  `net.ipv4.ip_unprivileged_port_start=0` before its `--sysctl` values, which win.
- An image without a shell gets a small program for `getent`, so `-u 1000:1000` runs
  on distroless and scratch images too, and one without `/usr` gets an empty one.

## Changed

- **`build -f` names the Dockerfile**, as with docker; `--force`, which replaces an
  image of the same name, has no short form any more.
- **`exec` runs as the machine's user**, its `--user` or else its image's `USER`, as
  docker exec does; `-u root` gives root. On a booted machine it runs as root.
- **`kill` ends the restarts of an app without a stop signal of its own on any
  signal**, as docker's kill does. With a stop signal (its image's `STOPSIGNAL` or
  `--stop-signal`), that signal and SIGKILL end them, and the policy decides for the
  others.
- **A `--depends-on NAME:completed` dependency runs until one run of it succeeds.** The
  machine is ordered after it and no longer wants it, so it runs first only when no run
  of it ended with 0, in this boot or, by the exit code the journal kept, an earlier
  one, and no longer at every start and restart of the machines that depend on it.
- **compose's `depends_on` is compose's own.** Its machines carry no `--depends-on`, so
  a service others depend on can be made anew, scaled down or removed while they run,
  as with docker compose.
- **Booted or app.** An image with an init is booted when it names no program (no
  entrypoint and no cmd), or its program is `init` or `systemd` by name, `/sbin/init`,
  `/usr/sbin/init`, or systemd wherever it is; `/init` and any other program make an
  app. An image keeps the mode it was
  installed with until it is pulled again.
- **Local images.** `run` and `create` look for a local image of a name under the
  configured registry, then as Docker Hub's (`app` as `docker.io/library/app`, an image
  compose pulled), and pull from the configured registry only when neither is there.
  An image a compose project builds whose name has no registry and no namespace is
  named under the configured registry, as `build -t` names it; one like `user/app`
  stays Docker Hub's.
- **docker's semantics in more places.**
  - `--entrypoint` drops the image's cmd, so only the arguments after it follow it, and
    an app with nothing to run is refused with docker's `no command specified`.
  - A `--tmpfs` given without options is mode 1777.
  - `stop -t` and `--stop-timeout` take a negative number for a stop that never kills.
  - `logs` shows the lines of the machine from its creation on, not those of a removed
    machine of the same name.
  - A volume made ahead is filled from the image of the first machine that takes it
    while it is empty.
  - A uid the image's passwd lacks runs with group 0 and `/` as home.
  - `update` keeps an unless-stopped machine stopped by hand off the boot list until
    its next start.
  - Healthcheck timings without a command are kept on an image without a healthcheck,
    and a test that no probe can run counts as none.
- **Flags.** `--restart on-failure:N` is taken, its count not kept, as systemd restarts
  on every failure; `--privileged`, `--read-only` and `--init` take `=false` and no
  longer take the next word as their value.
- **Machines.** Health probes run as the machine's user. `exec` and a probe into a
  paused machine fail at once instead of waiting. `kill` right after a start waits for
  the program to be running, so that the signal reaches it. `run` and `create` by
  reference take the image of that reference that never ran, the last pulled of
  several, never a machine of it.
- **Configuration.** `machines_dir` must be one of the directories systemd-nspawn finds
  machines in (`/var/lib/machines`, `/etc/machines`, `/run/machines`,
  `/usr/local/lib/machines`, `/usr/lib/machines`), and `state_dir` may neither be inside
  a directory machined lists images from nor hold one, where `machinectl clean` or
  `remove` would delete what nspawn keeps.
- **Signatures.** An attestation is not taken for a signature, and a listed signature
  whose manifest or bundle cannot be fetched fails the check unless a valid one is
  beside it.
- **References.** A reference by a sha384 or sha512 digest is refused, also in a
  Dockerfile's `FROM`; Docker Hub's names read as docker reads them.
- **`cp`** refuses a tree more than 2048 directories deep, a source ending in `/` or
  `/.` names the directory a link leads to, and a file that fails to read fails the
  copy without replacing anything.
- **Events** carry `created=` on machines and networks, which machine or network of the
  name it was.
- **`daemon --install`** also writes `nspawn-api@.socket`, `nspawn-api@.service`,
  `nspawn-auto-update.service`, `nspawn-auto-update.timer` (not enabled) and
  `/usr/lib/systemd/journald@nspawn.conf`; a binary installed by hand needs it run
  again.
- **On the bus.** `StartMachine` and `CreateMachine` take `addresses` and `gpus`;
  `GetImage`, `ListMachines` and `GetMachine` give `gpus`, `pid1`, `image_cmd` and
  `finished`; `ListImages` gives `image_only`, `created` and `pulled`; `Exec` without a
  user runs as the machine's own; `StopMachine` takes 18446744073709551615 for no
  timeout; `CreateSecret` takes `replace` and `replace_if_changed`; `JobOutput` carries
  lines queued back to back in one signal; a job keeps its last 1000 lines of `Output`.
  polkit asks for a password only when the call carries
  ALLOW_INTERACTIVE_AUTHORIZATION, as nspawn, busctl and systemctl set it; a call
  without it that needs one is refused at once. DBUS.md has the details.
- **Fixes.** `--dns-search` reaches booted machines too, as `Domains=` in their network
  files; `--sysctl` takes a value with spaces, `net.ipv4.ping_group_range=0 2147483647`
  among them; `/var/lib/nspawn/claims` is root's alone, like the rest of the state
  directory.

## Requirements

As for 1.10.0.

## Known gaps

- The mstack backend stays experimental and untested by this release: no host of the
  test matrix runs it, since it needs systemd 261 or a release after 262 (the 262
  release cannot boot a managed user namespace, systemd/systemd#43899). The Docker
  API, CDI devices and `network connect` are not available on mstack machines.
- GPUs have been tested with CDI specs written for the test suite only, not with real
  NVIDIA or AMD hardware.
- The builder does not forward SSH (`--ssh`), write outputs other than a local image
  (`--output`, `--cache-to`), take named or remote contexts, `ADD` of a git repository,
  attestations or other platforms, run `RUN --device` or `RUN --security=insecure`, or
  lint (`--check`, `--call`); `--cache-from` is ignored, and `COPY --link` copies as a
  plain `COPY`.
- The compose attributes COMPOSE.md marks as refused are refused with a reason by the
  commands that start the services they belong to.
