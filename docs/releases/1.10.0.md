nspawn 1.10.0 starts machines after the ones they depend on, at boot as well,
and prints the commands that make machines again on another host.

## Added

- **`--depends-on NAME[:CONDITION][:optional]`** on `run`, `create` and
  `start`, compose's `depends_on` for one machine, remembered like the other
  per-machine settings; `--depends-on none` forgets them.
  - The condition is `started`, the default (the other machine's start went
    through), `healthy` (its healthcheck says healthy; it needs one) or
    `completed` (its program ended with 0, as a migration does; it runs again
    at every start of the machines that depend on it, as with
    `docker compose up`). With `:optional` a failure of the other machine is
    a warning and the machine starts anyway.
  - systemd keeps the order: the machine's unit wants the other one's and is
    ordered after it, and its first hook, `nspawn await-dependencies`, waits
    for the condition, so `nspawn start`, `machinectl start`, a restart policy
    and a start at boot follow the same order. `start` says which machines it
    started first, and gives the dependency's failure as the reason when the
    start fails because of it.
  - A start that waits for `healthy` or `completed`, directly or further
    down the chain, has no time limit, and `nspawn stop` ends it. Stopping a
    machine leaves the ones that depend on it running, as compose does.
  - A machine on another one's network (`--network container:NAME`) that also
    depends on it gets it started first, by `nspawn start` as at boot.
  - The machines named must be nspawn's, a machine cannot depend on itself and
    a cycle is refused, `--network container:` counting as a dependency. `rm`
    refuses a machine others depend on, unless they are removed in the same
    command, and then removes it only once they are gone.
  - `inspect` and `GetImage` show it as `depends_on`, and the bus takes it as
    the `depends_on` option (as).
- **`nspawn generate [NAME...]`** prints a shell script that makes machines
  again, on another host or on this one: `network create` for the networks
  they join, then `run -d --pull always` with every flag each machine keeps,
  after the machines it depends on or takes its network from, which come
  along; an image without flags of its own is pulled again, unless another
  machine takes its network. Without names it covers every machine. What a
  flag cannot carry is said in comments at the top: secrets, encrypted for
  this host, host directories a machine mounts, and images built on this
  host. The contents of volumes and of a machine's writable layer, and its
  addresses, stay behind. On the bus it is `Generate(as names, a{sv} options)
  -> s`, which asks for `org.nspawn.inspect`.

## Changed

- **`rm` of a machine with the ones on its network.** Named in the same
  command, the machines that take their network from another one
  (`--network container:NAME`) are removed first and NAME after them, where
  1.9.1 refused NAME as long as a machine named it. One of them that stays,
  running without `--force`, keeps NAME with it.

## Requirements

As for 1.9.1.
