nspawn 3.3.2 lets the programs of a machine lock memory without `CAP_IPC_LOCK`, keeps
`run -d` of a program that ends at once from failing when many machines start together,
sends its errors to `nspawn logs` and asks a busy registry again.

## Fixed

- **Locking memory.** A machine that is not privileged may call mlock, mlockall and the
  rest up to its memlock limit, 8 MiB under systemd's default, which `--ulimit memlock=`
  changes. systemd-nspawn's system call filter refused them with EPERM unless
  `CAP_IPC_LOCK` was kept, so a program that locks a few pages, such as mongod with TLS,
  ended at start. A `RUN` step of a build may lock memory too.
- **A program that ends at once, among many starts.** Started while other machines
  started, a program that ended right away could end before the machine's publish hook
  did, and systemd failed the start job: `run -d` said `machine NAME failed to start`
  and an attached `run` gave that error instead of the program's exit code. The machine
  shows as exited, as it does when started alone.
- **`ps` and `compose ps`** said `Up 56 years` of a running machine that machined listed
  without a start time, which happens while it goes away; they say `Up`.

## Changed

- **Errors send you to `nspawn logs --all NAME`** where they said `journalctl -u
  systemd-nspawn@NAME.service`, which needs the adm or systemd-journal group: a failed
  start, a machine that ended right after starting or while booting, one that did not
  register, a dependency that failed, and the rest. A machine whose output is dropped
  (`--log-driver none`), which `logs` refuses, still points at journalctl.
- **A busy registry is asked again.** Every read of a registry (`pull`, `run`, `create`,
  a build's `FROM`, `hub tags`, auto-update and the Docker API's pulls) is asked again
  after 1, 2, 4 and 8 seconds when the registry answers 429 Too Many Requests or a 5xx
  error, and fails after the fifth answer with `the registry was still busy after 5
  tries` and the registry's message. Any other refusal ends it at once, and so does a
  download cut in the middle.

## Known gaps

- **Limits are not visible inside a machine.** `-m`, `--cpus` and `--pids-limit` bound
  the machine's unit, while its program runs in a cgroup below it, where
  `/sys/fs/cgroup/memory.max`, `memory.swap.max`, `cpu.max` and `pids.max` read `max`.
  A program that sizes itself from those files, as Node.js and the JVM do, takes the
  host's memory and CPUs and runs into the limit; give it its size, such as
  `--max-old-space-size` or `-Xmx`. docs/USAGE.md says more.

## Requirements

As for 3.0.0.
