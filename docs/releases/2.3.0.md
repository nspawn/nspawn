nspawn 2.3.0 applies image layers inside the tree they are extracted into and checks
each one against the digest its image names for it, takes arguments with newlines, and
reads more of the forms the flags take elsewhere.

## Security

- **Every entry of a layer is applied inside the tree it is extracted into.** An entry
  of a layer could have its extended attributes, owner and mode applied to a path
  outside that tree on the overlay and mstack backends. Each entry now lands where its
  name resolves inside the tree, a symlink's absolute target starting again at the
  tree's root and `..` stopping there, and whatever is done to the entry is done there.
- **Layers are checked against their image's config.** The digest of a layer's archive
  has to be the `diff_id` the config gives it, read to the archive's end, and an image
  whose config names another number of layers than its manifest is refused. The digest
  found is kept beside each extracted layer; a layer extracted without one has its blob
  read again the first time an image uses it.

## Fixed

- **ko-built images have their program** (crane, cosign and others): a name from the
  root down, such as `/ko-app/crane`, lands inside the layer.
- **More of what a layer holds is applied as it is written:**
  - a name with `..` stops at the layer's root;
  - an absolute symlink of a lower layer on an entry's path (`var/run -> /run`) is
    followed inside the tree on the flat backend;
  - a symlink and an entry below it in one layer no longer fail the pull;
  - an entry that changes its type within one layer replaces the earlier one;
  - the legacy regular type with a trailing slash is a directory;
  - a long name padded with more than one NUL is read.
- **Whiteouts:**
  - a whiteout of an empty, `.` or `..` name fails the layer instead of removing a
    directory;
  - an opaque marker spares what its own layer wrote;
  - the parents of a whiteout are made;
  - a whiteout of an entry of its own layer keeps that entry.
- **Entry metadata:**
  - hard links take their header's owner and mode;
  - PAX times keep their nanoseconds;
  - every `trusted.*` attribute of a layer is dropped;
  - the layer's root entry is left alone.
- **A layer's compression is told by its magic**: Docker's `diff.tar` type holding gzip
  and an empty blob under `+gzip` are read, OCI's uncompressed type stays as it is.
- **A flat pull that fails leaves the machine it replaces as it was** and no half tree:
  the layers are applied beside it and moved into place.
- **An image without layers starts on the overlay backend.**
- **Downloaded blobs are synced** before they are kept.
- **A `run --rm` machine whose program ends at once is removed.** The removal gave up
  while the start was still under way, and `compose down` found the machine left.
- **auto-update says `rolled back` only when the old machine runs again**; put back but
  not up is `failed`.
- **A mkosi build keeps the image version mkosi writes** from `ImageVersion=`; the tag
  stands in only for one it did not write.
- **A CDI spec file named `.yaml` or `.json` alone is read.**

## Changed

- **Arguments with newlines** (a script for `sh -c`) are taken from `run`, compose and
  an image's `CMD`: the program is started through the image's `/bin/sh`, which decodes
  them. An image without `/bin/sh` cannot take such an argument.
- **`-v`** takes the modes `z`, `Z`, a propagation, `nocopy` and the consistency ones,
  which do nothing; a source starting with `.` is relative to the directory of the
  command; a host source is cleaned; the same `-v` twice is one bind.
- **`--tmpfs`** takes tmpfs's own options. `noexec`, `nosuid`, `ro` and the atime
  flags, which systemd-nspawn cannot apply, are refused when the machine is made instead
  of failing its start.
- **`--label KEY`** is a label with an empty value; **`--restart`** takes `always:0`,
  `on-failure:` and an empty policy; **`--pids-limit -1`** removes the limit;
  **`--device HOST:MODE`** is the node at the same place; an unknown capability is
  refused.
- **`inspect -f json`** prints the objects on one line, and an object a template fails
  on is said after the others are printed.
- **auto-update**: `io.containers.autoupdate=image` is `registry`, `disabled` and an
  empty value are no updates, and a misspelt policy is `failed`, so that the run and
  its timer show it.
- **Healthcheck flags of 0 and an empty `--health-cmd`** keep what the machine has.
- **xz-compressed layers** are refused with a message.

## Known gaps

- A layer extracted by an earlier release is kept as it was extracted. `images rm` of
  the images that use it and a pull again extract it anew, which a ko-built image pulled
  with 2.2.1 or earlier needs to get its program.
- On the overlay and mstack backends, the directories a layer makes for entries
  without their parent entries take the default owner and mode, which hide those of
  the layers below. Layers written by BuildKit, docker and nspawn carry their parents.

## Requirements

As for 2.0.0.
