nspawn 1.5.1 fixes two things the first day of 1.5.0 turned up.

## Fixed

- **A service of another version is pointed out.** The service keeps running
  the binary it started with: after an upgrade it is the old one until it goes
  idle or is restarted, and a command of the new version got the old
  behaviour without a word, as a pull that never mentioned signatures did.
  Every command now reads the service's `Version`, and when it differs from
  its own it warns and says how to restart the service
  (`sudo systemctl restart nspawn.service`). The rpm and the deb restart it on
  upgrade themselves.
- **`rm` and `images rm` refuse a name nothing is behind.** Both cleaned up
  whatever a name might have left behind and said `removed` even when there
  was nothing at all, so a typo passed for a removal. A name with no record,
  no image machined knows, no leftovers and no boot link now fails with
  `no machine or image named NAME`, as docker refuses it, and the other names
  of the same command are still tried.

## Requirements

As for 1.5.0.
