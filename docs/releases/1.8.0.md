nspawn 1.8.0 keeps what machines print out of the system's journal.

## Added

- **`--log-driver local|journal|none`** on `run`, `create` and `start`, as
  docker takes it, remembered like the other per-machine settings.
  - `local`, the default, sends a machine's output to journald's `nspawn`
    namespace, a journal of nspawn's own apart from the system's, capped at
    1 GiB by `/usr/lib/systemd/journald@nspawn.conf` (override it in
    `/etc/systemd/journald@nspawn.conf`). `logs` and an attached `run` read it
    with `-f`, `-n`, `--since` and timestamps as before, and
    `journalctl --namespace=nspawn` shows every machine's.
  - `journal` keeps a machine's output in the system's journal.
  - `none` drops it: the unit gets `StandardOutput=null`, `logs` refuses the
    machine (a booted one's own journal is still there with `--inside`), and
    an attached `run` of an app still shows the output, straight from the
    program; should its caller go, the service reads and drops what comes
    until the machine ends, so that the program never blocks on it. A booted
    machine's console goes nowhere with `none`, so it runs with `-d`.
  - `inspect` and `GetImage` show it as `log_driver`, and the bus takes it as
    the `log_driver` option (s).

## Changed

- **Machines write to nspawn's journal namespace.** Machines of earlier
  versions follow the new default from their next start: their output leaves
  the system's journal, so `journalctl -u systemd-nspawn@NAME` shows only
  systemd's and the hooks' lines, and `journalctl --namespace=nspawn -u
  systemd-nspawn@NAME` the rest. `logs` shows both, what was written before
  included; `--log-driver journal` brings a machine back to the system's
  journal. Booted machines now start behind `nspawn attach-exec`, as apps
  already did, which connects their console to the namespace.

## Requirements

As for 1.7.2. nspawn-selinux lets the service connect to journald's stream
socket.
