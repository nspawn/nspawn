nspawn 3.1.0 gives app machines devices of the host that come and go, with
`--device-cgroup-rule`, and starts the apps in a user namespace that a bind of a file
system without idmapped mounts kept from starting: a user other than root with the
image's own getent, or a `-v` of `/dev`.

## Breaking changes

- **An app given devices of the host runs without a user namespace**, whatever its
  network: `--device`, `--device-cgroup-rule`, or a `-v` of a node or a directory of
  `/dev`. A device node cannot be idmapped, so only outside a user namespace does root
  inside open it as its owner and mode allow. Such an app has the capabilities of an
  app on a bridge network. A booted machine keeps its user namespace.
- **A machine that ran in a user namespace keeps its files' owners shifted when it
  later runs without one**: an app off the bridge given a device now, or one moved from
  `--network none`, `host` or `veth` to a bridge network. systemd-nspawn chowned the
  tree into the range it picked, and nothing shifts it back, so a user other than root
  inside no longer owns its files. Make such a machine anew (`nspawn rm`, then `run` or
  `create` with the device or the network).

## Added

- **`--device-cgroup-rule 'TYPE MAJOR:MINOR PERMISSIONS'`** on `run`, `create` and
  `start` (`c 189:* rwm`; `c`, `b` or `a` for both, a number or `*`, `r`, `w` and `m`),
  remembered like the other flags, `none` forgets them. The machine's cgroup opens
  nodes by their numbers, those that appear while it runs included:
  `-v /dev/bus/usb:/dev/bus/usb --device-cgroup-rule 'c 189:* rwm'` reaches a USB device
  that comes and goes, as a flasher's does. A rule for every minor of a major goes by
  the device groups the host's `/proc/devices` names after it at each start
  (`DeviceAllow=char-usb_device`), and is refused then for a major without one; one
  node goes by `/dev/char/189:3`. The bus takes it as the option `device_cgroup_rules`
  and records it under that key, compose as `device_cgroup_rules`, the Docker API as
  `HostConfig.DeviceCgroupRules` in a create and an inspect, and `nspawn generate`
  writes the flag.

## Fixed

- **An app in a user namespace starts with binds of file systems that take no idmapped
  mount.** `-u 1000 --network none`, or an image whose `USER` is not root, failed with
  `Failed to clone .../usr/bin/getent: Invalid argument` where the image has a getent
  of its own, and so did `--network none -v /dev/...`: every bind went in with `:idmap`,
  which overlayfs and devtmpfs refuse. A bind is idmapped where its file system takes
  it, as mountinfo has it; overlayfs, devtmpfs, proc, sysfs, NFS, CIFS, FUSE and tmpfs
  before Linux 6.3 go in as they are, their owners unmapped inside.
- **compose's support table** says which machines have a user namespace for
  `userns_mode`: an app on a bridge or with devices of the host has none.

## Requirements

As for 3.0.0.

## Known gaps

- A booted machine given devices of the host keeps its user namespace: root inside
  opens a node only as its mode allows anyone.
