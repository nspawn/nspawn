nspawn 1.6.0 hands a machine a network interface of the host, a wifi adapter
among them.

## Added

- **`--interface IFACE`** on `run`, `create` and `start`: a network interface
  of the host, moved into the machine while it runs and back on the host when
  it stops or is removed, with its name kept, as systemd-nspawn's `Interface=`
  and LXC's `phys` type do it. A wifi adapter goes with its whole phy, so a
  Kali machine gets the adapter for monitor mode and injection, which
  `--device` (nodes under `/dev`) and `--network host` (a user namespace may
  not configure the host's interfaces) never gave. Where systemd-nspawn makes
  the machine's network namespace (booted machines, `--network none`) the
  interface is an `Interface=` line of the settings file; an app on the
  bridge joins a namespace nspawn made, so the unit's hooks move the interface
  in with `ip`, or `iw` for a phy, and give it back. The flag is repeatable
  and remembered like the rest, `--interface none` forgets them, `inspect`
  and `GetImage` list them as `interfaces`, and the bus takes them as the
  `interfaces` option of `StartMachine`, `RunMachine` and `CreateMachine`.
  Refused: an interface another running machine has, one that is not on the
  host, `lo`, nspawn's own bridges and veth ends, a port of a bridge or bond,
  and machines with `--network host` or `container:NAME`; the host's default
  route interface is allowed with a warning. A wireless interface takes `iw`
  on the host for an app on the bridge (the packages recommend it) and
  systemd 256 for a booted machine or one with `--network none`, and the
  start says so when either is missing.

## Fixed

- **`/sys/class/net` in an app on the bridge listed the host's interfaces**,
  nspawn's own bridge among them, while `ip` showed the app's: systemd-nspawn
  counts a namespace path as a private network only with `Private=yes` or
  `--private-network` beside it, and without them it mounted the machine's
  `/sys` before joining the namespace. Both are written now, so sysfs is
  mounted inside the namespace, which tools like airmon-ng read.
- **`update` of a machine in another one's network.** On systemd before 259
  `update` rewrote the unit's ExecStart without the shared namespace of a
  `--network container:NAME` machine, so its next restart put it on a
  namespace of its own.

## Requirements

As for 1.5.0. `iw` is recommended, for wifi adapters given to an app on the
bridge; the e2e suite needs the `dummy` and `mac80211_hwsim` modules.
