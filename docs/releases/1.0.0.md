nspawn 1.0.0, the first stable release of the rewrite in Rust: a docker-like
client of systemd-nspawn and systemd-machined, with images from an OCI
registry, a bridge network of its own, and a service on the system bus that
does the work.

## What is in

- `pull`, `create`, `build` (mkosi), `push`, `search`, `login`, `logout`,
  `images`, `ps`, `start`, `stop`, `exec`, `shell`, `logs`, `network`.
- Backends: overlay, flat and mstack (systemd 261, managed user namespaces).
  Layers are shared between images and garbage collected.
- Images with an init system boot; anything else, Docker Hub images included,
  runs as an app under the stub init with the OCI config's entrypoint,
  environment, working directory, user and stop signal. `--entrypoint`, the
  arguments after `--`, `-e` and `-v` work as in docker.
- The nspawn0 bridge: fixed addresses, NAT, published ports (`-p`) reachable
  from outside, from the host and from 127.0.0.1, names of the other machines
  in `/etc/hosts`, coexistence with firewalld, docker and ufw.
- Unit hooks: `machinectl start`, enabled units and programs that exit on
  their own prepare and release their network like `nspawn start` does.
- Credentials per registry, checked at `login`; GitHub and GitLab registries
  work for pull, push and tags.

## New since the beta

- **A service on the system bus.** `org.nspawn` does everything the command
  line does, and the command line is a client of it, as machinectl is of
  machined. Long operations come back as job objects whose output arrives as
  signals; `exec` and `logs` hand over their streams and a process object with
  the exit status. The interface is in `docs/DBUS.md`. The bus starts the
  service on demand and it exits again after a minute of idleness.
- **A confined SELinux domain.** On Fedora and RHEL the service runs as
  `nspawn_t`, from the `nspawn-selinux` package, and commands run inside a
  machine take the machine's own context, as with docker exec.
- **Terminals inside the machine.** `exec` on a terminal allocates the pseudo
  terminal in the machine's own devpts, so `tty` and everything that opens its
  terminal by name work there.
- **Packages.** Fedora (rpm, with the policy as a subpackage), Debian and
  Ubuntu (deb), and Arch (PKGBUILD, plus `nspawn` and `nspawn-git` in the AUR).
  Each one was built and installed on its distribution, and the whole end-to-end
  suite passes on Fedora 44 with SELinux enforcing, on Ubuntu 24.04 and on
  Arch.
- Minimum systemd is 255, down from 259.

## Requirements

systemd 255 or newer with systemd-nspawn and machined, overlayfs, `ip` and
`nft`. The command line talks to the service on the system bus, so install the
package rather than a loose binary; `nspawn daemon --install` puts the service
in place for a build from source.

## Getting it

The RPM (with `nspawn-selinux`), the `.deb` built on Ubuntu 24.04, the Arch
package, the plain binary and a `SHA256SUMS` are attached below. The shell
completions and `man nspawn` come with every package.

## Known gaps

- Only root and whoever a polkit rule allows; there is no per-machine
  delegation.
- No signature verification of pulled images yet.
- No IPv6 on the bridge, no publishing on one host address only.
- The firewalld zone binding of the bridge does not survive
  `firewall-cmd --reload` until the next `start` or `nspawn network up`.
