nspawn 3.3.0 moves images and machines' files without a registry: `save` and `load`
carry images as a tar archive, `commit` makes an image of what a machine changed,
`export` writes a machine's files as a tar and `import` makes an image of one. The
Docker API serves them too.

## Added

- **`nspawn save IMAGE... [-o FILE]`** writes images to one tar archive: an OCI image
  layout with the Docker image archive's `manifest.json` beside it, which `nspawn load`
  and `docker load` read. The blobs go as the store keeps them, so an image keeps the
  digests its registry gave it. A terminal is refused as the output.
- **`nspawn load [-i FILE] [-q]`** adds the images of such an archive, or of one
  `docker save` wrote, plain or compressed with gzip, zstd or bzip2: each image under the
  name its reference gives, placed as `build -t` places one, the image for this host
  taken from an index of several platforms. The whole archive is checked before an image
  is installed.
- **`nspawn commit MACHINE REPOSITORY[:TAG]`** makes an image of what a machine changed
  over its image, with the machine's settings on top of the image's (but the labels
  that place it in a compose project) and its mode, boot or app; `-c` applies
  Dockerfile instructions to them (`CMD`, `ENTRYPOINT`, `ENV`, `EXPOSE`, `HEALTHCHECK`,
  `LABEL`, `ONBUILD`, `STOPSIGNAL`, `USER`, `VOLUME`, `WORKDIR`), `-a` and `-m` give the
  author and the comment. A running machine is frozen while its files are read
  (`--pause=false` lets it run). Owners come out as the image has them, whatever user
  namespace the machine runs in; volumes, binds and tmpfs stay out, and so do the files
  nspawn and systemd-nspawn write for the machine (`/etc/hosts`, `/etc/resolv.conf`,
  `/etc/hostname`, `/etc/machine-id`, `/etc/localtime`), the empty files and directories
  made to mount on, the links to `/usr` systemd-nspawn makes, the journal directory of
  the machine's ID, and the file capabilities systemd-nspawn's own chown into a user
  namespace took, which the image keeps.
- **`nspawn export MACHINE [-o FILE]`** writes a machine's tree as a tar, owners as its
  image has them, without its volumes, binds and tmpfs; a running machine runs on.
- **`nspawn import FILE|- REPOSITORY[:TAG]`** makes an image of one layer from the tar of
  a root filesystem, with `-c` and `-m` as for `commit`.
- **The Docker API** serves `GET /images/get`, `GET /images/{name}/get`, `POST
  /images/load`, `POST /commit`, `GET /containers/{id}/export` and `POST /images/create`
  with `fromSrc=-`, which answered 501; an import from a URL still does. Loads and
  imports show in its events.
- **The bus**: `SaveImages`, `LoadImages`, `ImportImage`, `CommitMachine` and
  `ExportMachine`, with jobs of kinds save, load, import, commit and export.

## Changed

- **An image committed, loaded or imported is made on this host**, as a built one is:
  its record's origin says commit, load or import, `auto-update` leaves it alone, and
  `generate` says to push it before its script runs elsewhere ("was made on this host").

## Fixed

- **A machine in a user namespace keeps its files' capabilities.** A booted overlay
  machine, or an app off the bridge without devices, is shifted into its namespace's
  range at its first start. systemd-nspawn did that with a recursive chown, after which
  the kernel clears every file capability, so `arping`, `newuidmap` and the like lost
  theirs inside. nspawn shifts the tree itself before systemd-nspawn starts, with the
  capabilities, the setuid and setgid bits and the IDs of ACL entries, and systemd-nspawn
  takes that range and changes nothing. A machine shifted already keeps what it has; one
  made again from its image gets them.
- **`wait` and `run` give the exit code once the machine is down.** They answered when
  the program ended, while the unit's hooks after the end still ran and `ps` and
  `inspect` showed the machine running: `ps --filter exited=N` right after could miss
  it.
- **`cp` waits for a start systemd makes.** `cp` to or from a machine that `machinectl
  start` or another machine's dependency was starting read or wrote its files while
  their owners were being shifted into its user namespace; it is refused until the
  machine runs, as a start nspawn makes is.

## Known gaps

- `commit` and `export` refuse mstack machines, whose root exists only inside them
  while they run.
- A flat machine's changes are found by reading its whole tree and its image's layers.
- `load` refuses an image the archive gives no name (`docker save` of an image by its
  ID), since nspawn keeps an image under its name; so does a commit without a
  repository through the Docker API, and a config in the body of `POST /commit` that
  sets anything.
- `compose commit` and `compose export` are still refused.

## Requirements

As for 3.0.0.
