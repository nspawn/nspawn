nspawn 2.2.1 gives an app's program the notify socket of systemd-nspawn back, which 2.2.0
emptied.

## Fixed

- **An app's program finds systemd-nspawn's `NOTIFY_SOCKET` again**, as with 2.1.0.
  2.2.0 set it empty for apps, which libsystemd's and Rust's sd_notify refuse with
  EINVAL: continuwuity panicked as it started. A program that notifies systemd as a user
  other than root logs that it could not, as with 2.1.0, and goes on; `-e NOTIFY_SOCKET=`
  (or `NOTIFY_SOCKET: ""` in a compose file's `environment`) quiets one that takes an
  empty value for none.
- **A build step keeps systemd-nspawn's notify socket** instead of an empty value: a step
  is the PID 1 of its systemd-nspawn, and as root it notifies without an error.

## Requirements

As for 2.0.0.
