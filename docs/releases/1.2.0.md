nspawn 1.2.0 makes `run` behave like `docker run`, lets machines be grouped on
networks of their own, and reports what happens to them: `events`, `stats`,
`kill` and `update` are new.

## Breaking changes

- **`run` stays attached.** Like `docker run`, it now follows the machine's
  output until the machine ends and exits with its exit code. `run -d` does
  what `run` did in 1.1.2: start the machine and return. Scripts that called
  `run` to start a machine in the background need `-d`; `--no-wait` is only
  accepted with it.
- **`network ls` lists networks.** It listed the machines of the bridge, which
  are now under `nspawn network inspect bridge`. `network ls --json` changes
  with it. The `ListNetwork()` method of the bus is still there for 1.1
  clients.
- **The `ExecStart=` of app machines.** The hooks drop-in of every app machine
  now runs systemd-nspawn through `nspawn attach-exec`, on every systemd
  version, which is how `run -i` and `run -t` reach the program. An
  administrator's own drop-in that resets `ExecStart=` and sorts after
  `nspawn-hooks.conf` leaves that machine without `-i` and `-t`, and `run` says
  so. The drop-in is rewritten at the next start of each machine.

## New

- **run, attached.** `nspawn run -it --rm docker.io/library/alpine:3 sh` does
  what docker does: a terminal for the program, the machine removed once it
  ends. As there, what follows the image is the program's command and
  arguments; `--` before them still works. Without `-t`
  the output follows a line at a time (stdout and stderr together, read from
  the journal, so `logs` has it later and the machine goes on should `run` be
  interrupted), `-i` passes standard input to the program, and Ctrl-C,
  SIGTERM, SIGHUP and SIGQUIT go to the program; a third Ctrl-C within a
  second detaches. The exit code is the program's, or 128 plus the signal it
  died of (137 after `kill`). A booted image shows its console until it powers
  off; `run -it` on one opens a root shell once it has booted and powers it off
  when the shell ends. `--rm` also works with `-d`, and refuses a restart
  policy; as with docker, an image it had to pull is kept (under the image's
  local name, the machine getting a name of its own), so the next run does not
  download it again.
- **User-defined networks.** `nspawn network create backend` makes a bridge of
  its own (`nsbr-backend`) with the next free /24 of `network_pool`
  (`10.99.0.0/16` unless set in nspawn.toml, never one the host already
  routes) or the one given with `--subnet`; `--network backend` on `start`,
  `run` or `create` puts a machine on it. Machines of one network reach each
  other by name and nothing of another network reaches them; ports they
  publish are reachable from everywhere through the host, as from the LAN.
  `--internal` makes a network with no way out. `network rm`, `network prune`
  and `network inspect` complete it; `network up` brings up every network.
- **events.** `nspawn events` reports what happens to machines (`start`,
  `die` with its exit code, `stop`, `restart`, `oom`, `fail`) and what nspawn
  does (`pull`, `build`, `create`, `push`, `kill`, `update`, `remove`, and the
  creation and removal of networks and volumes), as it happens or between
  `--since` and `--until`, filtered by name, type, event or label, as text or
  `--json`. It reads the journal, so machines started at boot, by `machinectl`
  or by a restart policy are there too.
- **stats.** `nspawn stats` shows what each running machine uses: CPU, memory
  against its limit, network, disk and processes, redrawn every second;
  `--no-stream` for one reading, `--json` for scripts.
- **update.** `nspawn update web -m 1g --cpus 2 --restart always` changes the
  limits and the restart policy of a machine; a running one gets the new limits
  at once.
- **kill.** `nspawn kill [-s SIGNAL] NAME...` sends a signal to the program of
  an app or the init of a booted machine. SIGKILL, the default, stops the
  machine for good; the machine's own stop signal does too, as with docker;
  any other signal leaves it to the restart policy should the machine end.

On the bus: `RunMachine`, `KillMachine`, `UpdateMachine`, `MachineStats`,
`Events`, `ListNetworks`, `GetNetwork`, `CreateNetwork`, `RemoveNetworks` and
`PruneNetworks`, and the option `remove` of `StartMachine`; see
`docs/DBUS.md`.

## Fixed

- The journal no longer drops the output of a machine that writes a lot
  (`LogRateLimitIntervalSec=0` in the hooks drop-in).
- `logs` showed `[N B blob data]` for every line with colours or a carriage
  return, which is most of what a program on a console writes; it shows the
  line.

## Requirements

As for 1.1.2: systemd 255 or newer with systemd-nspawn and machined,
overlayfs, `ip` and `nft`; `cp` needs Linux 5.6 or newer. nspawn-selinux
gains rules for `/run/nspawn`, the service's structured journal entries and
the machines' network counters.

## Known gaps

The gaps of 1.1.2 remain, but those `run` had. A machine joins one network.
The output of an attached run without `-t` is line based, with stdout and
stderr together. Closing the terminal of `run -t` stops the machine, since
nothing reads its terminal any more; `-d` and `exec` are for machines that
stay.
