nspawn 1.1.2 adds `run`: a machine made from an image and started in one step.

## New

- **run.** `nspawn run nginx:1.27 --name web -p 8080:80` does what `pull`
  and `start` do together, like `docker run -d`. It takes the flags of both
  (`--name`, `--backend`, `--mode`, and `-p`, `-e`, `-v`, `-l`, `--restart`,
  `-m`, `--cpus`, `--pids-limit`, `--network`, `--entrypoint`, `--no-wait`
  and the arguments after `--`), which the machine keeps as after `start`.
  `--pull missing`, the default, makes the machine from a local image with the
  same reference, as `create` does, and asks the registry only when there is
  none; `--pull always` asks it every time and `--pull never` never. A name
  that is taken is refused with a pointer to `start`, unless `--force`, which
  makes the machine anew. It returns once the machine runs: `nspawn logs -f
  NAME` follows its output.

The service's interface is unchanged: `run` is the command line calling
`PullImage` or `CreateMachine`, then `StartMachine`.

## Requirements

As for 1.1.1: systemd 255 or newer with systemd-nspawn and machined,
overlayfs, `ip` and `nft`; `cp` needs Linux 5.6 or newer.

## Known gaps

As for 1.1.1. `run` does not attach to the machine's output as `docker run`
without `-d` does, and has no `--rm`.
