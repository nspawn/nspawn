nspawn 1.3.1 makes the `mstack` backend opt-in. The systemd 262 release
cannot boot a machine in a managed user namespace, and the pieces mstack
rests on (systemd-nsresourced, systemd-mountfsd) are still settling, so it
is experimental until they are not.

## Changed

- **`--backend auto` is overlay** on every host (flat where the kernel has
  no overlayfs). It chose mstack on systemd 261 or newer.
- **mstack is experimental.** `--backend mstack` (or `backend = "mstack"` in
  the configuration) works where systemd 261 or newer has systemd-nsresourced
  and systemd-mountfsd, with a note saying so, and what the host's systemd
  makes of it is the host's business. The systemd 262 release cannot boot a
  managed user namespace at all: its nsresourced denies the machine's init
  the cgroups it needs, so it dies with `Failed to create /init.scope
  control group`. This is exactly 262 as released, reported as
  [systemd/systemd#43899](https://github.com/systemd/systemd/issues/43899)
  (it comes from the rewrite of the userns-restrict BPF program in
  [#43196](https://github.com/systemd/systemd/pull/43196)), and a later
  version with the fix will boot mstack machines again. Existing mstack
  machines are kept as they are; on 262, pull the image again with
  `--backend overlay` to run it. Nothing is converted.

## Fixed

- **Events carry the same metadata whatever the action.** `machine remove`
  said nothing of the image, `network remove` nothing of the network, and
  volumes and secrets nothing at all, while `create` did. Every event of a
  kind now carries the same attributes: `image=` on a machine's (`pull`,
  `create`, `build`, `push`, `kill`, `update`, `pause`, `unpause`,
  `health_status`, `remove`), `subnet=`, `interface=` and `internal=` on a
  network's, `path=` on a volume's, `size=` on a secret's, written with the
  event so that they are there once the record is gone.
- **`top` right after a `restart`** could list systemd-nspawn itself instead
  of the machine's processes: it now waits for the machine's cgroup and never
  lists the host's own processes.

## Requirements

As for 1.3.0. The test matrix is Ubuntu 24.04 (systemd 255), Fedora 44 (259,
SELinux enforcing) and Arch (262).
