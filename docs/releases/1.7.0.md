nspawn 1.7.0 lets a machine's swap and time zone be chosen, and keeps a
command entered with `exec` from holding a capability the machine only has
behind its seccomp filter.

## Added

- **`--memory-swap SIZE`** on `run`, `create`, `start` and `update`, as
  docker takes it: memory and swap together. Equal to `--memory` gives the
  machine no swap, a larger size gives it the difference, and `-1` lifts the
  bound on swap; `0` goes back to the default, as much swap again as memory.
  A total needs `--memory`, and one below it is refused. `inspect` and
  `GetImage` show it as `memory_swap`, and the bus takes it as the
  `memory_swap` option (x) of `StartMachine`, `RunMachine`, `CreateMachine`
  and `UpdateMachine`.
- **`--timezone MODE`** on `run`, `create` and `start`: systemd-nspawn's
  `Timezone=` (`auto`, `off`, `copy`, `bind`, `symlink`, `delete`),
  remembered like the other per-machine settings. Its default, `auto`, points
  `/etc/localtime` at the host's zone at every start, so a zone set inside a
  booted machine was lost at the next one; `off` leaves the machine's own.
  `auto` forgets the setting; the bus takes it as the `timezone` option (s).

## Changed

- **exec in an app on the bridge goes without CAP_SYS_BOOT.** Since 1.6.1
  such an app keeps the capability so that a reboot from inside ends it, with
  the kexec system calls filtered out. A command entered with `exec` gets the
  machine's bounding set but not its seccomp filter, and in the host's user
  namespace the capability is the host's, so the command goes without it.
  The machine's own processes keep it, as do commands in a machine with a user
  namespace of its own or with `--privileged`. The reboot(2) system call from
  a command entered with `exec` now fails with EPERM; `nspawn restart` restarts
  the machine from the host.

## Requirements

As for 1.6.1.
