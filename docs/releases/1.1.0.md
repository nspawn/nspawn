nspawn 1.1.0 makes a machine something you can run a service in: it comes back
when it dies, it cannot take the whole host, its files can be copied in and out,
and scripts read everything about it as JSON.

## New

- **Restart policies.** `start --restart` and `create --restart` take docker's
  `no`, `on-failure`, `always` and `unless-stopped`. A machine that ends is
  started again after a second, then later and later up to half a minute, with
  its address, ports and volumes; `ps` shows it as `restarting` meanwhile.
  `always` and `unless-stopped` also start the machine at boot, and
  `nspawn stop` takes an `unless-stopped` machine off the boot list until the
  next `start`. `nspawn stop` always stops a machine, one waiting to be
  restarted included; an `always` machine still starts at the next boot.
- **Resource limits.** `-m`/`--memory`, `--cpus` and `--pids-limit` bound the
  whole machine through its unit (MemoryMax=, CPUQuota=, TasksMax=); as with
  docker, `--memory` also allows as much swap again, and no more.
- **Machine-readable output.** `inspect NAME...` prints machines and images,
  running or not, as JSON, like docker inspect, and `ps`, `machines ls`,
  `images ls`, `network ls` and `volume ls` take `--json`. On the bus,
  `GetMachine` returns one machine.
- **Labels.** The image's own labels (`OciLabels=` in mkosi, `LABEL` in a
  Containerfile) are kept, and `--label KEY=VALUE` on `start` and `create`
  adds the machine's own; both show up in `inspect` and `ps --json`.
- **cp.** Files and directories between the host and a machine, running or
  stopped, with docker cp's rules. What goes in belongs to root inside the
  machine, what comes out to whoever ran `cp`, and paths inside the machine
  are resolved inside it, so no link there leads to the host.
- **rm.** `nspawn rm NAME...` removes machines, and `rm -f` stops a running
  one first. `images rm` removes the same things as before (see Changed).
- **Named volumes.** `volume ls` shows them with the machines that use them,
  `volume create` makes one ahead of time, `volume rm` and `volume prune`
  remove the ones nobody uses. Removing a machine keeps its named volumes and
  says so.

All of it is on the bus too: `GetMachine`, `RemoveMachines`, `CopyFrom`,
`CopyTo`, `ListVolumes`, `CreateVolume`, `RemoveVolumes`, `PruneVolumes`, and
the new options of `StartMachine` and `CreateMachine`. See `docs/DBUS.md`.

## Changed

- Stopping a machine that already ended now stops its unit as well, so a
  machine between two runs of its restart policy, or a guest that is rebooting,
  is stopped for good instead of coming back.
- `images rm` and `pull --force` refuse a machine whose unit is still up or
  restarting even when machined no longer lists it.
- `ps` lists containers only. machined also registers the virtual machines of
  libvirt and others, which nspawn can neither enter nor stop; naming one to
  `exec`, `shell`, `logs`, `stop`, `cp` or `inspect` says so.
- Machines and the bridge no longer get IPv6 link-local addresses. The bridge
  carries IPv4 only, and machined handed the `fe80::` address out ahead of the
  bridge address, so a machine's name led a host to it first.

## Requirements

As for 1.0.0: systemd 255 or newer with systemd-nspawn and machined,
overlayfs, `ip` and `nft`. `cp` needs Linux 5.6 or newer (openat2).

## Known gaps

- Limits and policies apply at the next start; there is no `docker update` for
  a running machine.
- `cp` has no `-L`, no `-a` and no `-` for tar streams; hard links arrive as
  separate files, extended attributes and file capabilities are not carried,
  and devices, sockets and fifos are left out. A stopped mstack machine cannot
  be copied into or out of. Where SELinux enforces, a host directory mounted
  with `-v` keeps its label, which the service may not write to; named volumes
  work.
- Only root and whoever a polkit rule allows; there is no per-machine
  delegation.
- No signature verification of pulled images yet.
- No IPv6 on the bridge, no publishing on one host address only.
