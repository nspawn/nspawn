nspawn 1.6.1 closes a way out of an app machine and fixes what a review of
the whole code turned up.

## Security

- **Apps on a bridge network kept CAP_SYS_ADMIN outside a user namespace.**
  Such an app runs without a user namespace, since one cannot join the
  network namespace nspawn prepares on the host, and it kept systemd-nspawn's
  default capabilities, `CAP_SYS_ADMIN` among them, while systemd-nspawn's
  seccomp filter allows the mount system calls. Root inside the app could
  remount `/proc/sys` writable and name a program in `kernel.core_pattern`,
  which the kernel runs as root in the host's namespaces: root on the host,
  from any image run on the default network. Apps without a user namespace
  (a bridge network, or `--network container:NAME`) now keep a default set of
  their own: docker's default capabilities, the set every image is written
  for (CHOWN, DAC_OVERRIDE, FOWNER, FSETID, KILL, MKNOD, NET_BIND_SERVICE,
  NET_RAW, SETFCAP, SETGID, SETPCAP, SETUID, SYS_CHROOT, AUDIT_WRITE), plus
  SYS_BOOT, so that a reboot asked from inside still ends the machine as it
  does in a booted one (in its own pid namespace a reboot can only signal
  the machine's init, and the kexec system calls are filtered out).
  `--cap-add` puts a capability back, as with docker (`NET_ADMIN` for a VPN
  client), an interface given with `--interface` keeps `NET_ADMIN` on its
  own, and `--privileged` keeps them all. Booted machines and apps with
  `--network none`, `veth` or `host` run in a user namespace of their own
  and keep systemd-nspawn's set as before. Package managers, ping, users
  switched and ports bound work as before; what needs more says so with an
  EPERM, and `--cap-add` is the answer.
- **cp out of a running machine walked into /proc and /sys.** A copy of `/`
  entered the kernel's file systems mounted inside the machine, `/proc/kcore`
  among them, the size of memory. Directories on those file systems are left
  out.
- **A volume target, a tmpfs path, a device path or a secret target with a
  `.` or `..` component** resolved elsewhere once mounted (`-v /srv:/.` put
  the host directory over the machine's root). Every such path must be plain.
- **A layer download had no bound but its digest**, checked once the registry
  stopped sending: the size the manifest declares is the bound now. A
  registry named without a dot or a port (a host of the local network) was
  read back as a repository of Docker Hub, so pulls and the credentials of
  the catalog went there; it is kept as the registry it is.

## Fixed

- **Ports.** A machine that ended withdrew every port of its record by key,
  so a port it published in an earlier run and another machine held by now
  went with it: a stop of the stopped machine, or its unit failing to start
  on the conflict and retrying under a restart policy, cut the other
  machine's port. Only the entries that lead to the machine's own address go.
- **Flags of `run`, `create` and `start`.** `--ulimit NAME=unlimited` wrote
  a number systemd refuses and dropped with the whole line; `--device` with
  a directory (`/dev/dri`, `/dev/snd`) bound it but let no node under it be
  opened; `--add-host HOST=IPv6` split the address on its first colon; a
  capability both added and dropped was dropped; a quote in a volume target
  broke the unit that makes a booted machine wait for its volumes; `--sysctl`
  on a machine without a namespace of its own and `--secret` on an mstack
  machine were refused after the record had been written, so the next start
  failed the same way; `create --force` validated its flags after the old
  machine was gone; `create` did not inherit `--network none`; `run --rm`
  with `--pull always` or `--mode` replaced whatever machine had the
  image's name, with a force nobody gave; `logs -n 0` showed ten lines;
  `--password-stdin` without `--username` read the password as the username.
- **Machines.** `kill` left its marks when the signal could not be sent, so
  the restart policy did not bring the machine back and its exit code read
  as a death by that signal; a program that failed before the machine
  registered made `start` fail instead of ending with the program's code;
  two attached runs of one name broke each other's socket; the interfaces a
  veth machine bound to firewalld's trusted zone stayed bound when the
  machine ended on its own; the decrypted secrets of a start that failed
  stayed under `/run`; the exit code of a stopped machine could be a hook's
  instead of the program's.
- **Images.** A volume made on first use was seeded from one layer of the
  image, not from the image as it shows; `pull`, `build` and `create` with
  `--force` removed the old machine before an extraction that could fail;
  garbage collection took an unreadable records directory or manifest for an
  empty one; an mstack tree with eleven layers or more read the wrong top
  layer; an upper layer that could not be removed was left behind without a
  word; `mkosi` output that was not UTF-8 ended the reading of the build,
  which then hung on its pipe; the hint a key bundle declares, which nothing
  authenticates, was recorded instead of the key that verified; a catalog
  name with a dot passed for another registry in `search`; a credentials
  store with a hand-written alias ignored a fresher login, and one that
  could not be read made every operation anonymous without a word;
  `hub.nspawn.org:443` slipped past the built-in policy; a registry that caps
  its pages below what is asked was listed to its first page; a relative
  `--ca-cert` reached the service as written.
- **The service.** A call counted as busy only once polkit had answered, so
  a caller who took longer than the idle time to authenticate found the
  service gone; the output of `exec -d` was drained by tasks of the runtime,
  which kept the service from exiting when a child of the command outlived
  it; an integer option refused the `t` type the documentation promises;
  polkit's absence was reported as a raw bus error, and so was a missing
  service when the version was read.
- **exec, health and cp.** `exec -u` takes names for USER:GROUP, the home
  of the passwd entry and the supplementary groups of /etc/group; the
  command gets the machine's resource limits (`--ulimit`), not the service's;
  an `exec` right after a start waits until systemd-nspawn has confined the
  machine, since systemd-nspawn reports it started as soon as its init
  process exists, before that process drops its capabilities, and such a
  command could get the full set; a
  terminal is attached only when both standard input and output are one, so
  redirected output is byte-exact; SIGTERM or SIGHUP during a terminal
  session put the terminal back; `run -t` without `-i` no longer feeds
  standard input to the program, and a session ended no longer swallows
  what is typed next; a health probe that left a child behind holding its
  output no longer hangs the runner, and a probe counts in the start period
  by when it started; the getent stand-in reads a last line without a
  newline; `cp` into a machine writes beside the file it replaces and
  renames over it once complete; the terminal a command gets in a machine
  with private users belongs to the machine's root, not to nobody; the
  mount helper of an mstack machine reports without the stream locks.

## Requirements

As for 1.6.0. nspawn-selinux gains the rules the fixes above need: a
process group for the command of `exec` and the health probes, and the
kind of file system `cp` reads under each path.
