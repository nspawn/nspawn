nspawn 3.2.0 reads the name of a machine or an image one way in every command: an image
goes by its local name and by its reference alike, so `images rm somos/app:1` and
`run somos-app-1` work as `images rm somos-app-1` and `run somos/app:1` do. `run` of an
image just built or pulled makes its machine beside it, and TAB after `logs -f` offers
the machines that run.

## Changed

- **Every command takes an image by its local name or its reference**: `run`, `create`,
  `push`, `rm`, `images rm`, `inspect`, `images inspect`, `start`, `stop`, `exec`,
  `logs`, `network connect` and the rest. A text that can be a machine's name is a name,
  the record of that name or nothing, as the methods of the bus take it, so that `rm -f
  app` run again never removes an image of `app:latest`; the commands that take an
  image, `run`, `create`, `push`, `images rm` and `images inspect`, read a name nothing
  here has as a reference too (`nspawn images rm busybox` takes the image of
  `busybox:latest`, whatever its name). Any other text is the reference of an image,
  under the configured registry first and then as a Docker Hub name, and names the image
  pulled or built for it. A reference never names a machine made from the image (`rm
  nginx:latest` removes the image and leaves those machines), but where the image is
  only read (`inspect`, `images inspect`, `push`), when no image of it is left. A
  reference of no image here is refused with `no local image of REFERENCE` by `images
  rm`, and with `no machine or image of REFERENCE` by `rm` and every command that takes
  a machine (`stop`, `exec`, `logs`, `inspect` and the rest), which refused it as an
  invalid machine name; `start` adds how to pull it. A name a record has is that record
  for `run` too, as for `create`: where a build of `app` went beside a machine or an
  image of another reference named `app`, `nspawn run app` takes that record, and the
  build runs by its reference (`nspawn run app:latest`) or by the name the build gave
  (`app-2`).
- **`run` never consumes or replaces an image**: where an image has the name `run` gives
  its machine (`nspawn build -t app:1 .`, then `nspawn run app:1` or `nspawn run app-1`,
  as `build` says to), the machine goes beside it, under the first free `NAME-N`
  (`app-1-2`), which a note says, and the image stays for the next run, with `--force`,
  `--pull always` or `--mode` too. It was refused as a machine that exists, whose
  `nspawn start` would have made the image itself the machine, and `--force` pulled over
  the image. A machine that has the name is still refused. A record whose name is no
  reference (`MyApp`) runs by its name, and a pull of a record's name asks for the
  reference the record goes by.
- **`ps --filter ancestor=`** takes a local image's name, and a reference under the
  configured registry, as every command reads one.
- **TAB after `logs -f`** (`--follow`, `-tf`) offers the running machines alone; `logs`
  without it still offers every machine and image. TAB after `run` offers the local
  images too.
- **`network connect` and `network disconnect`** of a name nothing has say `no machine
  or image named NAME`, as the other commands do.
- **The bus**: `ResolveImage` takes the option `names` (b), a record of that name before
  a reference, which the command line asks for each reference it is given. Every method
  that takes the name of a machine or an image takes a reference that can be no
  machine's name (`busybox:1.37`), read the same way; a name is the record of that name,
  as it is, the source of `CreateMachine` included. `GetImage` of nothing here says `no
  local image of NAME`, and `PushImage` of an image that is not here fails with
  `NoSuchImage`.
- **A first component that starts with a dot is no registry** (`../x` is no reference).

## Requirements

As for 3.0.0.
