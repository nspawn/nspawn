nspawn 2.1.0 publishes ports on the host's IPv6 addresses too, as docker does.

## Added

- **Published ports answer over IPv6.** `-p 443:443` is reached on the host's IPv4
  addresses, as before, and on its IPv6 addresses, TCP and UDP, so HTTP/3 works over
  both. The machines keep IPv4 addresses alone and nftables cannot translate IPv6 into
  IPv4, so the IPv6 side is a proxy in user space, as docker's userland proxy is: a
  transient unit per machine, `nspawn-proxy-NAME.service`, that the unit's hooks start
  once the machine runs and stop with it.
  - It listens for IPv6 alone, so the IPv4 port stays nftables' DNAT, and relays TCP
    connections and UDP datagrams to the machine's address. UDP replies leave from the
    address the client wrote to, so QUIC works on a host with several addresses; a UDP
    flow is forgotten after 90 seconds without traffic.
  - Its capabilities are bounded to `CAP_NET_BIND_SERVICE` and its address families to
    IPv4, IPv6 and Unix sockets.
  - `start` and `run` say so when the proxy is not up a few seconds after the machine;
    the IPv4 side works all the same.
- **`-p` takes an IPv6 address**, in brackets: `-p [::1]:8080:80`, `-p
  [2001:db8::1]:443:443`, ranges included. `-p [::]:80:80` publishes on every IPv6
  address alone. A link-local address cannot be named, as it needs an interface;
  `[::]` takes it with the others. An IPv4-mapped address is refused.
- **The bindings of a running machine**, docker's way: `nspawn port` and `ps --format
  '{{.Ports}}'` print `0.0.0.0:8080->80/tcp` and `[::]:8080->80/tcp`, as do `nspawn
  compose ps` and `port`, and the Docker API's `Ports` and `NetworkSettings.Ports`.
  `ListMachines` and `GetMachine` give them in a new key, `bindings`.
- **compose's `ports.host_ip` takes IPv6 addresses**, which nspawn compose refused.

## Changed

- **`-p 0.0.0.0:H:C` publishes on IPv4 alone**, as with docker. It meant the same as
  `-p H:C` before. A machine whose ports were published before 2.1.0 gains the IPv6
  side at its next start, `0.0.0.0` ones included, since earlier releases stored them
  without an address; `-p 0.0.0.0:H:C` given again keeps such a port to IPv4.
- **The port checks cover the IPv6 side**: a port another running machine publishes
  there, or one a service of the host listens on over IPv6, refuses the start, with
  the same messages as on IPv4.
- **`generate` writes an IPv6 address of `-p` in brackets.**
- **The SELinux policy lets nspawn bind ports below 1024** (`net_bind_service`), for
  the proxy's listeners.

## Requirements

As for 2.0.0. An IPv6 client comes in through the host's input path, not its
forwarding, so a host firewall (firewalld's zone of the interface, ufw, an nftables
input policy) has to let the port in, as for any service of the host; nspawn changes no
rule for it.

## Known gaps

- A machine sees an IPv6 client as the bridge's gateway address, not the client's own,
  as with docker's proxy. The PROXY protocol towards the machine is not offered.
- Machines still have no IPv6 address of their own.
